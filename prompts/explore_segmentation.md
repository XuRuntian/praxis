# Praxis：从人工范例探索到批量切分

请执行下列完整流程，不只给出计划，也不要停在方法说明或代码生成阶段。

开始前由用户填写或指定：

- 数据根目录：`<DATA_ROOT>`
- 任务清单：`<TASKS_JSON>`（dataset、task_id、exemplar_ids、target_ids）
- 本轮方法目录：`<RULES_ROOT>`（使用新目录，不覆盖历史版本）
- 本轮输出目录：`<OUTPUT_DIR>`（必须尚不存在）
- 目标数据是否有 GT 且需要独立评分：`是 / 否`

## 目标和边界

读取 AGENTS.md 和 docs/RULE_SPEC.md。根据清单指定的人工标注范例，逐任务探索可复用的切分方法，再由 Praxis 批量切分其余数据。本轮只做物理切分，不生成动作描述，不使用视频。不同任务可以有不同数量的范例；两范例不是系统限制。方法与验证过程必须能由保存的代码和命令重放。

只以指定范例的人工切分作为探索依据。探索时不查看目标轨迹、目标标注或历史目标预测/成绩来选择方法。不要通过文件名推断切分答案。自动注入的相关历史背景如实记入方法说明，不因一般背景停止，也不宣称严格盲测。实验目录中已有冻结方法不应覆盖；若任务是从已有方法继续开发，明确记录来源和改动。

## 1. 检查并固定本轮输入

核对清单、范例 ID、文件、通道名称、帧索引、时间戳和人工边界。范例与目标不能重合；不自行改变指定范例。缺少清单或路径时先报告具体缺项，不浏览全部标签自行选答案。当前流程需要人工范例，无范例任务记录为不支持本轮探索，不能编造范例。

如果源标注文件混有范例和目标，写机械提取代码，仅返回指定范例记录，不打印整个标注文件。不把目标标注、视觉列或标签派生列放进物理输入。可以机械检查目标文件存在性和 schema，不能向研究阶段展示目标轨迹或答案。

保存本轮实际使用的启动指令、任务清单以及范例物理文件/标注内容/通道信息的来源和哈希。记录可获得的 Agent 型号和配置；无法获知时写 unknown，不猜测。不要记录密钥。

## 2. 逐任务探索并验证

查看范例全程与人工边界附近的物理信号，必要时绘图。提出可检验的解释，例如事件、状态转换、运动变化或阶段轨迹对应；自主选择实现方法，不预设统一算法，不限于 observation.state。

用范例实际执行候选方法，检查预测边界、漏切、多切和误差。有多个范例时可互相迁移检验；只有一个时明确只有范例内检查。方法选型已经使用这些范例，不能把此验证称为独立测试。

若方法不能解释范例，继续诊断、修改或换方法，不仅调一个统一阈值。不要按固定帧号、episode ID 或时长比例硬编码答案。也不要为提高输出率无证据地放宽拒绝条件。没有统一的合格误差阈值；基于事件证据说明可用范围和剩余误差。

无需穷举所有算法。找到有依据的方法后交付；确实不能建立方法时明确记录未解决原因，可交付返回 None 的方法以保留批量覆盖记录，不称为成功研究。不要因为一个任务未解决停止其他独立任务。

## 3. 保存最小交付与可重放证据

每任务放在 `<RULES_ROOT>/<task_id>/`，提供 rule.py，实现 segment(episode) 返回切分点或 None；需要模板时按 RULE_SPEC 提供 load(directory)，参数和模板自由组织。

方法说明写在简短 README 中：使用的范例、信号、主要候选和选择依据、实际误差、未解决问题、执行命令。保存产生关键参数/模板和验证结果的探索或验证脚本；这些脚本仅使用指定范例，输出到独立研究目录，不覆盖已冻结方法。不要求重放每一次临时尝试，但不能只留下无法重建的手工参数或截图。

把实际启动指令、输入哈希与验证命令放在方法目录内已有说明或一个小记录文件中，使 runner 自动把它们纳入冻结资源。用于方法的必要模板随目录交付，大图和完整原始数据仍留在外部，并记录来源。固定随机种子，列出新增依赖及已验证版本。

先用最终 rule.py 入口跑范例验证，不能只验证一段与最终代码不同的研究代码。检查原始帧映射、切分点递增、单片段和拒绝情况。不要修改 Praxis 核心来适配某个任务；接口缺陷应明确报告。

## 4. 自动批量执行

所有任务的方法和范例验证完成后，固定本轮版本。执行：

```bash
praxis run --data-root <DATA_ROOT> --tasks <TASKS_JSON> \
  --rules-root <RULES_ROOT> --output <OUTPUT_DIR>
```

run 会在执行前记录资源哈希，并保留所有目标的结果。不要手工生成目标切分答案。运行后不得根据目标错误或成绩修改本轮方法、参数、模板或预测；修复必须另开版本。遇到执行阻塞保存实际状态，不伪称完成。数据错误与方法拒绝分开说明。

## 5. 可选独立评分和交付

若用户指定目标有 GT 且需要评分，在全部预测完成后执行 `praxis score --run <OUTPUT_DIR> --data-root <DATA_ROOT> --output <独立的新评分文件>`。评分器读取真值，研究阶段只查看汇总。没有 GT 或不需要评分时，输出完整预测和状态统计即可，不把缺少评分当作流程失败。

交付方法目录、复现命令、实际处理数、有效输出/拒绝/错误数和未解决问题；有独立评分时附 F1@50/F1@75。区分范例验证与目标测试，不将有效输出率解释为正确率。不需要用户逐步批准探索、验证与执行，只在确实缺少必要输入或存在无法解决的冲突时询问。
